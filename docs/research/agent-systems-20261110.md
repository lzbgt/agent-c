# Agent systems research used for the current design

Checked: 2026-11-10. These are primary sources inspected for this change, rather than a claim to cover every recent paper or to establish a universal SOTA ranking. The April comparison remains a historical snapshot. Recommendations below are design inferences; upstream functionality is not functionality shipped by Agent-C.

| Source | Relevant observation | Decision for Agent-C |
| --- | --- | --- |
| [LangGraph persistence](https://docs.langchain.com/oss/python/langgraph/persistence) | Checkpointers preserve thread state; stores preserve knowledge across threads. | Keep execution state, durable knowledge, and prompt context separate. A memory checkpoint is not an execution checkpoint. |
| [Microsoft Agent Framework workflows](https://learn.microsoft.com/en-us/agent-framework/concepts/workflows/) and [checkpoints](https://learn.microsoft.com/agent-framework/workflows/checkpoints) | Typed executors and inspectable graphs coexist with model-driven agents; checkpoint identity must remain compatible across restoration. | Compile SOP authoring into a versioned execution representation and keep agent reasoning inside bounded actions. |
| [Pydantic AI durable execution](https://pydantic.dev/docs/ai/capabilities/durable_execution/overview/) | A durable engine journals requests/tool operations; settled-step snapshots provide a different persistence guarantee. | Define recovery boundaries explicitly. Preserve the native C/C++ runtime; an external durable backend can be an adapter later. |
| [Temporal activities](https://docs.temporal.io/activities) | Activities are retryable units; external side effects should be idempotent. | Workflow submit dedupe cannot guarantee an external command occurs once. Introduce stable effect IDs and reconciliation before expanding production writes. |
| [Anthropic long-running harnesses](https://www.anthropic.com/research/effective-harnesses-for-long-running-agents) | Incremental work, persistent progress, and explicit verification address cross-context continuity and premature completion. | Durable requirements and evidence should drive continuation. Compaction alone cannot establish completion. |
| [Anthropic managed-agent architecture](https://www.anthropic.com/research/managed-agents) | Sessions, harnesses, and execution environments can have separate stable interfaces. | Separate execution facts, loop policy, and host/MCU capabilities. Avoid binding the portable core to a cloud service. |
| [Codex non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode) and [CLI](https://learn.chatgpt.com/docs/codex/cli) | Non-interactive execution, session continuation, and machine-consumable integration are useful harness surfaces. | Add explicit exec/resume/session entry points around the existing executor and retain JSONL evidence. This is inspiration, not wire compatibility. |
| [DeepSeek Harness architecture](https://deepseek-harness.github.io/deepseek-harness/en/reference/) | Scoped capability services, durable session facts, replaceable drivers, and shared launcher profiles separate product composition from the agent loop. | Keep one implementation of host capabilities across CLI/daemon; separate command dispatch and advance toward explicit lifecycle ports. Do not import a second runtime just for plugins. |
| [DeepSeek tool calls](https://api-docs.deepseek.com/guides/tool_calls/) and [thinking mode](https://api-docs.deepseek.com/guides/thinking_mode/) | Tool conversations have provider-specific metadata and history requirements despite API-shape compatibility. | Preserve opaque provider continuation data in a future transcript format. Verify actual routes, streaming and tool round trips before advertising compatibility. |
| [Recursive Language Models, v3, 2026-05-11](https://arxiv.org/abs/2512.24601v3) | Long input can be treated as an external environment inspected through bounded operations and recursive calls. | Experiment with artifact-backed context queries on gateways/hosts, with depth and cost limits. Do not put arbitrary recursive execution on MCUs by default. |
| [Google's agent scaling study, 2026-01-28](https://research.google/blog/towards-a-science-of-scaling-agent-systems-when-and-why-agent-systems-work/) | Coordination benefit depends on task structure; sequential tasks can degrade with more agents. | Default to one executor and allocate specialists for independently verifiable branches; compare cost and quality against that baseline. |
| [MCP specification](https://modelcontextprotocol.io/specification/2026-07-28) and [A2A](https://a2a-protocol.org/latest/) | Tool/context integration and remote agent collaboration have distinct protocol roles. | Add optional host adapters; retain the compact embedded wire protocol. Neither protocol supplies transactional side-effect guarantees. |
| [llama.cpp](https://github.com/ggml-org/llama.cpp) | Local C/C++ inference is a deployable host capability. | Use a provider adapter or local server on capable gateways; the ESP32 C execution core is not an assertion that a general LLM fits on the MCU. |

Upstream pages can change. No upstream libraries or repositories were imported, and no popularity/star-count comparison is used to justify the design. Before implementing a protocol adapter, pin and test its exact negotiated version. In particular, the DeepSeek Harness source describes a preview product; that is not evidence of production guarantees for Agent-C.
